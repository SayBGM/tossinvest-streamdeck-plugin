# 프로젝트 개선 검토 — 2026-09-08

시세 조회 전용 범위를 유지하면서 코드, 72/96/144px 카드, 설정 화면, 테스트, 설치 패키지를 검토했다. 기능 확장보다 연결 안정성과 표시 정보의 정확성을 우선했다.

## 검토에서 확인한 문제

| 우선순위 | 문제와 영향 | 개선 방향 |
| --- | --- | --- |
| 높음 | 토큰 발급 대기 중 구독 목록을 연속 변경하면 WebSocket이 두 개 생성됨. 연결 중 소켓을 닫을 때 오류 리스너를 먼저 제거하면 비동기 오류로 프로세스가 종료될 수 있음 | 연결 시도 공유, 세대별 결과 무효화, 종료가 끝날 때까지 오류 처리 유지 |
| 높음 | 늦게 도착한 REST 응답이나 역순 체결이 더 최신의 가격을 덮어씀 | 시각을 검증하고 최신 시세만 반영 |
| 높음 | 새 거래일 체결을 전일 기준가·상하한가·이평선으로 판단해 잘못된 시그널이 발생할 수 있음 | 거래일 전환 시 이전 일자 데이터 무효화, 갱신 전 시그널 억제 |
| 높음 | 캐시 가격이 있으면 구독 거절을 무시하고 정상 연결 상태로 표시함 | 종목별 구독 상태와 가격 보존을 구분 |
| 높음 | 이미지 전송 Promise를 버리고, 렌더 큐가 실패도 성공으로 기록함 | 전송 완료를 기다리고 직렬화, 실패 처리와 재시도, 삭제된 키의 늦은 완료 무시 |
| 보통 | 색상 변경과 단일 키 새로고침에도 전체 종목을 조회함. 모든 일봉 조회가 끝나야 최초 구독과 렌더링이 진행됨 | 표시 변경의 불필요한 I/O 제거, 요청한 종목만 갱신, 기본 가격과 구독을 부가 정보보다 먼저 제공 |
| 보통 | 화면 갱신 주기나 시그널 표시 시간을 바꿔도 OAuth 인증을 다시 요구함 | 자격증명 저장과 표시 설정 저장 경로 분리 |
| 보통 | 설정창은 종목명만 있으면 ‘연결됨’으로 표시하고, 좁은 선택 상자에서 테마 설명이 잘림 | ‘종목 확인됨’과 통신 연결 상태 구분, 간결한 선택 문구와 폭에 맞는 배치 |
| 보통 | 패키지 검증이 기존 체크섬을 비교하지 않고 새로 덮어씀. 실행 검사는 압축 파일 대신 작업 폴더의 번들을 사용함 | 기존 체크섬 비교, 핵심 파일 검사, 실제 압축 해제본으로 호스트 등록 확인 |

초기 재현 검사에서는 중복 연결, REST 시세 역행, 거절 후 정상 상태 유지, 거래일 전환 시 잘못된 기준가 사용을 확인했다. 설치된 `ws`를 사용한 별도 프로세스에서도 연결 중 정리할 때 처리되지 않은 오류로 종료되는 동작을 확인했다. 재현용 임시 테스트는 분석 후 제거했으며, 수정에 필요한 회귀 테스트는 정식 테스트에 포함한다.

위 표의 개선은 이번 작업에 반영했다. 시세 경합과 세션 처리는 Terra, 렌더링·패키지·설정 화면은 Luna가 구현했고 부모 에이전트가 통합 검토와 전체 검증을 수행했다. 추가 검토에서 동일 시각 REST 응답의 상태 회복, 캔들 대기 중 당일 고가·저가 누적, 저장 버튼 복구, 입력 초안 보존, 패키지 검사 프로세스의 자연 종료까지 보완했다.

## 화면 평가

- 현재가를 가장 크게 표시하고 상승·하락 방향을 아이콘으로 함께 보여주는 구성은 유지한다.
- 72px에서는 고가·저가와 긴 시그널 문구가 여전히 작은 보조 정보다. 실제 장비에서 책상 거리 가독성을 별도로 확인해야 한다.
- 종목 설정을 먼저 보여주고, 전체 키에 적용되는 표시 옵션은 별도 하단 카드로 분리한다. 미리보기는 72px를 기본으로 유지한다.
- 시그널을 가격 변화 알림으로 설명한다. 실제 기업 뉴스나 재료를 분석하는 기능은 아니다.

## 후속 작업 진행 결과

| 항목 | 구현 및 검증 결과 |
| --- | --- |
| 연결 정체 감지 | 핸드셰이크 15초, 60초 PING 후 JSON pong 응답 15초 제한. timeout 때 half-open 소켓을 즉시 폐기하고 재연결한다. 거래 틱 없이 pong만 오는 정상 상태, 오래된 소켓의 응답 격리, 재시도 타이머를 검증했다. |
| 응답 데이터 검증 | `response-validation.ts`에서 사용하는 필드만 검증한다. 잘못된 종목·시세 행은 분리한다. 손상된 일봉은 해당 종목의 일봉 전체를 거부해 이동평균이 더 오래된 거래일로 채워지지 않게 했다. 입력 심볼·통화 불일치·비정상 체결 가격을 차단하고 Retry-After 숫자/HTTP-date를 처리한다. |
| 구독 한도 안내 | 100개의 고유 종목만 실시간 구독한다. 초과 키는 현재가와 ‘주기 조회’ 안내를 유지하며, 설정창에 복구 방법을 표시한다. 슬롯 반환 후 자동 복구 및 반복 REST 갱신에도 안내가 유지되는지를 검증했다. REST는 200개 단위로 나눈다. |
| 책임 분리 | `runtime/quote-state.ts`, `refresh-coordinator.ts`, `subscription-plan.ts`로 종목·세션 상태, 비동기 갱신 소유, 구독 계획을 분리했다. |
| 시그널 계산량 | 등락 단계마다 Set에 값을 채우던 반복문을 방향별 최대 단계 두 값으로 교체했다. 극단적인 가격 비율에서도 계산량과 메모리가 증가하지 않는다. |
| Mac 호스트 | Stream Deck 7.4.2 / 내장 Node.js 20.20.0에 검증한 패키지를 적용했다. 실제 새 프로세스 시작, 시세 키 3개, 미국 종목 가격 갱신, ‘시세 서버 연결됨’ 표시, 표시 설정 저장, 페이지 전환 후 복구를 확인했다. |
| Windows | 사용자가 Windows 환경이 없음을 확인했다. Mac 및 자동 테스트로 범위를 조정했으며 Windows 실기기 통과를 주장하지 않는다. |

연결 감시와 응답 검증은 [공식 AsyncAPI](https://openapi.tossinvest.com/openapi-docs/latest/asyncapi.json)와 [공식 OpenAPI](https://openapi.tossinvest.com/openapi-docs/latest/openapi.json)를 확인해 구현했다. 실제 OS 절전·복귀와 물리 키의 책상 거리 가독성은 모의 타이머·화면 스냅샷과 별도 검증 항목이다.

## 검증 범위

수정 전 타입 검사·단위 테스트 73개·빌드·브라우저 테스트 6개가 통과했다. 브라우저는 샌드박스 실행 제한을 해소한 뒤 다시 실행했다. 초기 분기 커버리지는 WebSocket 약 45%, REST 약 55%여서 정상 경로뿐 아니라 연결 취소·재시도·역순 응답·세션 변경 검사를 우선 보강한다.

수정 후 최종 검증 결과:

| 검사 | 결과 |
| --- | --- |
| `npm run verify` | 타입 검사, 단위 테스트 85개, 빌드 통과 |
| `npm run test:ui` | Chromium UI·카드 테스트 10개 통과 |
| `npm run package:plugin` | 설치 패키지와 SHA256SUMS 생성 완료 |

| 실패 경로 검증 | 잘못된 체크섬을 거부하며 원본 체크섬 보존, 잘못된 패키지 실행 경로에서 무한 대기 없이 실패 확인 |
| 정적 점검 | 변경 diff 공백 검사 및 UI·스모크 스크립트 JavaScript 문법 검사 통과 |

위 표는 최초 개선 단계의 검사다. 이후 Node.js 20 및 실제 Mac 호스트 검사까지 확대했으며, 최신 결과는 다음과 같다.

### 후속 작업의 최신 검사

- 실제 Stream Deck 내장 Node.js 20.20.0으로 **전체 단위 테스트 110개 통과**. `node node_modules/vitest/vitest.mjs run`으로 실행했다.
- 같은 Node.js 20으로 Chromium UI 테스트 **11개 통과**. 새 한도 안내 카드의 144/96/72px 스냅샷과 문서 이미지를 확인·갱신했다.
- Node.js 20으로 타입 검사, Rollup 빌드, 핵심 산출물 검사, 설치 패키지 생성, 기존 체크섬 비교, SDK 로드와 압축 해제본의 모의 호스트 등록을 모두 통과했다. 브라우저·로컬 포트 및 빌드는 필요한 샌드박스 실행 제한을 해소한 뒤 검증했다.
- 사용자가 별도 프록시 작업을 제외했음을 확인했다. 최종 소스와 패키지는 프록시 변경을 포함하지 않는다.
- Mac 기존 설치 파일 11개를 백업한 뒤 패키지 파일을 적용했다. 설치된 번들의 바이트가 검증한 빌드와 일치하는지 확인했다. CLI 성공 문구만으로는 프로세스가 바뀌지 않아, 실행 위치를 확인한 기존 TossInvest PID만 SIGTERM으로 종료했다. 이후 실제 새 Node.js 20 프로세스 시작을 확인했다.
- 새 프로세스에서 오류 로그 유무를 원문·자격증명 출력 없이 확인했다. 설정창 연결 표시, 실제 미국 시세의 변화, 표시 설정 저장 성공, 원래 페이지로 복귀한 뒤 세 키 복구를 확인했다.
- Windows 실기기, 실제 OS 절전·복귀, 물리 키의 책상 거리 가독성, 원격 CI·릴리스 게시 및 다운로드 검증은 별도다. 프로세스 일시 정지·재개 검사는 OS 전체 절전 검사와 구분한다.

### v0.3.0 릴리스 후보 — 2026-09-09

- 패키지·잠금 파일 버전은 `0.3.0`, Stream Deck 매니페스트는 `0.3.0.0`으로 동기화했다.
- Node.js 20에서 타입 검사, 단위 테스트 110개, UI 테스트 11개, 빌드와 패키지 검사를 통과했다.
- PI 검증은 실제 설치 아카이브의 `sdpi.js`와 번들을 사용한다. 잘못된 실행 경로와 SIGTERM을 무시하는 자식 프로세스에서도 검사 실패·종료·임시 파일 정리를 확인했다.
- 전역 설정 요청과 키별 설정·메시지의 context 분리는 [공식 Elgato UI WebSocket 계약](https://docs.elgato.com/streamdeck/sdk/references/websocket/ui/)에 맞췄다. 실제 SDK actionStore와 PI 간 왕복도 통과했다.
- 최종 코드 리뷰에서 출시를 막는 P1/P2 문제는 발견하지 못했다. 원격 CI와 배포 파일의 결과는 GitHub Actions 및 해당 릴리스에서 확인한다.
